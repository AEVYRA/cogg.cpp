# v0.8.1 — memory/routing and self-runtime repairs

This maintenance change fixes two reproduced defects at the boundaries of
Phases 4–7. It introduces no database migration, model prompt change, semantic
retrieval service, or Phase 8 perception adapter.

## Open obligations must not disable an explicit fallback route

Trigger: two open tasks, a first executor whose memory policy admits one item,
and an explicitly configured second executor with room for four items.

Previously, the candidate selector raised a generic `Error` before projection.
`RoutedRuntime` only recognizes `ContextOverflow` as a capacity failure, so the
whole route stopped without trying the second executor. Byte/token overflows
already followed the intended path.

The selector now raises `ContextOverflow` for the item-count limit too. The small
executor is skipped before inference/admission charge; the larger executor sees
both open tasks and can commit. No task is dropped and no route is added implicitly.

## Self-runtime must retain failure causes

Previously, any backend exception became `backend_failed`. This also caught the
HTTP adapter's typed timeout/transport/credential errors, and returned before
checking whether cancellation or the overall inference deadline had occurred.

`SelfRuntime` now preserves the existing `FailureKind` categories, checks
cancellation and elapsed deadlines after both successful and exceptional backend
returns, and writes the resulting status to the attempt ledger. It retains the
same subject head, pending request and admitted-attempt accounting. Untrusted
provider exception messages remain excluded from results and durable diagnostics.

## Regression evidence

Both new targeted regressions failed on v0.8.0 before the fixes:

- `routing`: `memory pressure: too many open tasks` stopped the route.
- `self-state`: `self runtime lost typed failure` on a typed backend timeout.

The added joint memory/self fixture records an open commitment, a fact and its
source-linked summary, corrects the fact, then adds 80 unrelated deposits. After
a new Store/backend and index reconstruction, the bounded four-item context
contains the corrected fact and excludes the stale summary. The original source
is still addressable and the commitment's exact terms and creation version are
unchanged. A recent-only four-item projection misses the older fact in this fixture.
This tests evidence selection/recovery, not an LLM's ability to answer from it.

Final local GCC 12 / Debian validation: **10/10** CTest suites in Debug (46.15 s)
and **10/10** with ASan/UBSan (113.36 s), both with HTTP and self-state enabled.
No live provider calls or native inference reruns were needed for these host-layer
repairs. The reproduction and validation logs are retained locally in
`~/.local/state/cogg/repair-20260908/`.

The GitHub build matrix now enables `COGG_SELF=ON` in both normal and sanitized
jobs. Previously the Phase 7 tests ran locally but were absent from those jobs.

## Still open

Synonym-only retrieval and evidence-aware answer quality remain open, as do
large naturalistic comparative evaluations. These repairs do not establish a
general quality improvement across models. The pinned Phase 3 observation keeps
its original binary, database, protocol and deadline.
